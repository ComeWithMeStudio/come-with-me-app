# Колискові: фонове відтворення та перехід між треками
Ретроспектива 2026-11-11. **Статус: проблема відкрита, причину остаточно не доведено.**

## Симптоми зі збереженої історії тестів
У списку 13 колискових на телефоні автоматичний перехід між треками міг спрацювати з активним екраном, але при погашеному екрані наступна композиція не стартувала. Після розблокування перехід відбувався. Перемотування приблизно за 30 секунд до кінця давало інший результат, ніж природне догравання. Після циклу 13→1 відтворення могло зупинятися. Ці спостереження — результати повідомлених ручних тестів, не автоматичний тестовий звіт.

## Чого не можна стверджувати
- Не доведено, що Media Session сам по собі забезпечує перехід при вимкненому екрані.
- Не доведено, що проблема в Supabase чи пошкодженому MP3.
- Не підтверджено, що фінальний перехід 13→1→2 працює при заблокованому екрані.
- Не слід називати проблему виправленою без тесту на реальному пристрої.

## Шпаргалка для наступної діагностики
1. Записати модель телефона, версію Android, браузер/PWA, стан екрана та режим економії енергії.
2. Окремо протестувати: 1→2, 2→3, 13→1→2; природне завершення і перемотування до кінця; активний та заблокований екран.
3. Логувати події `ended`, `pause`, `play`, `visibilitychange` і відхилення Promise від `audio.play()` (без приватних даних).
4. Відрізняти зупинку поточного аудіо від відмови браузера запускати новий файл у фоні.
5. Зберігати результат кожного тесту разом із версією коду; не міняти кілька незалежних механізмів без проміжної перевірки.

**Примітка:** це документування історії, а не внесення виправлення.
