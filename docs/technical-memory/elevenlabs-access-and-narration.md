# ElevenLabs: ретроспектива доступу, озвучення та інтеграції
Дата складання: 2026-11-11. **Статус: частково відновлено; невирішене не вважати виправленим.**

## 1. Проблема доступу асистента до ElevenLabs
За збереженою історією розмов 2026-10-29 користувачка й асистент намагалися отримати доступ для генерації репліки через ElevenLabs. Посилання/підтвердження не пропускало користувачку, навіть при швидкому переході; повідомлення вказувало на необхідність повторного доступу асистента. Повторні спроби не дали підтвердженого підключення. Користувачка обрала відкласти цей крок до роботи з ноутбука. **Точний текст помилки, її першопричина та спосіб виправлення не встановлені.**

### Не повторювати без перевірки
- Не називати успішним підключення лише за фактом надісланого листа чи посилання.
- Не робити висновок, що причина — в акаунті, API, пошті або правах, доки не отримано текст помилки й журнал спроб.
- Не запускати платну генерацію для перевірки без потреби та погодження.

- Чи генерується озвучення автоматично через API та завантажується в репозиторій: **не підтверджено**.
- Чи всі репліки в усіх іграх відтворюються на мобільних пристроях: **не перевірено цією ретроспективою**.

## Шпаргалка на наступний випадок
1. Записати точний текст повідомлення про доступ, дату, дію, з якої виникла помилка; без паролів і токенів.
2. Окремо перевірити: доступ до сервісу → генерація → збереження MP3 → завантаження в сховище → URL у коді → запуск і завершення аудіо.
3. Для кожного кроку фіксувати «працює / не працює / не перевірено».
4. Перевірити наголос, звук на телефоні, повторний запуск, перехід до наступної сцени, фінал.
5. Додавати коміт і результат перевірки, не приписуючи причин без доказів.
